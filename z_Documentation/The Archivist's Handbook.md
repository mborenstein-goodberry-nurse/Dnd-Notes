# The Archivist's Handbook

*An operating manual for the Wanderer's Guide and its chronicles.*

> [!info] Welcome, prospective archivist
> You need not master every arcane mechanism to record a grand adventure. We strongly recommend, however, learning which buttons create entire folders before pressing them at random.

**Start here:** This handbook is for anyone using this Obsidian D&D vault. When I began developing this vault for my own campaigns, I experimented with many different methods to do what I wanted to do. While I've settled on a system that works, **you do not need Git, ChatGPT, recordings, transcripts, or a particular style of campaign to use it.** Those 'advanced processes' are documented in the [[z_Documentation/02 - Workflow Catalog|optional and advanced workflows]] for you to use or disregard. Enjoy!

**Documentation status:** These chapters are based on a **static review of the Development vault** provided November 10, 2026. The procedures still need to be verified in Obsidian.

## Read the labels

| Label | What it means | Example |
|---|---|---|
| **Core** | How the vault works; includes any requirements for a particular feature | A campaign calendar is needed before creating a standard dated Session Journal |
| **Recommended** | A good way to keep records useful and consistent; not enforced by the software | Write a neutral session chronicle and separate theories |
| **Optional** | An enhancement you can choose to use | AI help from your own notes, or AI help using recordings and transcripts |
| **Maintainer-specific** | How the original project is developed or maintained; **not** a user requirement | Our personal Git branch structure and historical migration process |

## Principles of the archive

- A new user should be able to use the vault entirely by hand.
- Document the simplest supported approach first, then alternatives.
- Preserve original evidence and mark uncertainty rather than filling gaps with guesses.
- Keep observed events, character knowledge, out-of-character information and theories distinct.
- Explain the **reason** for conventions without presenting preferences as software requirements.
- Make instructions self-contained enough that an unfamiliar human—or an unfamiliar AI given the appropriate files—can follow them.

> [!tip] A note on the jokes
> Fantasy humor appears in introductions and margins. It does **not** replace a command, a prerequisite, a safety warning, or an explanation of what a button actually does.

*Archivists are advised to record the dragon's name before discovering whether it wishes to be recorded.*
